# arxiv-daily-researcher 功能吸收审核计划

**目标**
先从 46 个 fork 里整理出值得吸收的合理功能候选，不进入具体实现路径。你审核后，我们再把被选中的功能拆成详细实现方案。

**高优先级候选**

| 优先级 | 功能 | 来源 | 价值 | 建议 |
|---|---|---|---|---|
| P0 | 论文级持久化、断点续跑、失败恢复 | `q1w2e3r4-1/arxiv-daily-researcher` | 避免日报运行中断后丢状态；让“已处理历史”更可靠 | 强烈建议吸收 |
| P0 | 修复“过早标记已处理”问题 | 当前代码 + q1 fork 思路 | 现在论文可能在深度分析/报告失败前就被标记为已处理，导致下次跳过 | 强烈建议修 |
| P1 | WebUI 里浏览历史论文、按状态筛选、人工过滤 | `q1w2e3r4-1` | 从“看 HTML 报告”升级成可管理的研究库 | 建议吸收 |
| P1 | 全局 LLM 请求池/限速器 | `q1w2e3r4-1` | 避免并发请求过多触发限流，提高稳定性 | 建议吸收 |

**中高优先级候选**

| 优先级 | 功能 | 来源 | 价值 | 建议 |
|---|---|---|---|---|
| P1 | Topic Discovery / 主题探索模式 | `hyperchem/arxiv-daily-researcher` | 适合探索新方向：大范围候选论文 + 相关性重排 + Top-N 输出 | 建议吸收 |
| P1 | 趋势研究的相关性分数缓存 | `hyperchem` | 减少重复 LLM 打分，降低成本 | 建议吸收 |
| P2 | OR/AND 关键词匹配模式 | `hyperchem` | 让趋势研究既能精准搜索，也能宽松探索 | 建议吸收 |
| P2 | 只把最终入选论文写入历史 | `hyperchem` | 避免候选池论文被过早排除 | 建议吸收 |

**数据源扩展候选**

| 优先级 | 功能 | 来源 | 价值 | 建议 |
|---|---|---|---|---|
| P2 | OpenReview 数据源 | `smallflyingpig/arxiv-daily-researcher` | 对 ML/AI 会议论文很有价值 | 建议吸收 |
| P2 | Hugging Face Papers 数据源 | `smallflyingpig` | 适合 AI 热点论文发现 | 建议吸收，但需谨慎处理页面抓取稳定性 |
| P2 | Papers with Code 数据源 | `smallflyingpig` | 可发现带代码/任务榜单的论文 | 建议吸收 |
| P3 | DBLP 数据源 | `smallflyingpig` | 对会议/作者/出版物检索有帮助 | 可选 |
| 不建议默认 | Google Scholar 数据源 | `smallflyingpig` | 价值有，但抓取脆弱、反爬和合规风险高 | 不建议作为默认功能 |

**产品增强候选**

| 优先级 | 功能 | 来源 | 价值 | 建议 |
|---|---|---|---|---|
| P2 | Zotero/BibTeX/本地论文库兴趣画像 | `Researcher-Feng/zotero-arxiv-daily` 思路 | 根据用户已有文献推荐新论文，比关键词更个性化 | 建议作为独立增强方向 |
| P3 | 基于已有论文的新旧权重推荐 | 同上 | 新读过的论文权重更高，推荐更贴近当前兴趣 | 可选 |
| P3 | 个人研究画像导入/导出 | 同上延伸 | 方便迁移配置和复用兴趣模型 | 可选 |

**暂不优先吸收**

| 内容 | 原因 |
|---|---|
| 旧版 Docker/WebUI/报告模板实现 | 当前主项目大多已有对应能力 |
| 个人配置、实验报告、生成数据 | 不适合作为通用功能 |
| 大量旧 fork 中的重复实现 | 多数是当前项目已有功能的早期版本 |
| 过于领域化的会议评分模板 | 可放在 examples/experiments，不建议进入默认主流程 |

**建议审核顺序**

1. 先确认 P0：论文级持久化、断点续跑、历史标记修复。
2. 再确认 P1：Topic Discovery、LLM 请求池、WebUI 历史管理。
3. 然后确认 P2：OpenReview、Hugging Face Papers、Papers with Code、Zotero 兴趣画像。
4. P3 功能可以等核心稳定后再考虑。

**默认建议**

第一轮最值得做的是：

- 论文级持久化 + 断点续跑
- 修复过早标记已处理
- 全局 LLM 请求池
- Topic Discovery
- OpenReview / Hugging Face Papers / Papers with Code 三个数据源

这些功能能明显提高稳定性、可用性和发现能力，而且和项目现有方向最一致。
